# 0.1.9 — 2026-09-21

## Changed

- **Stateless session mode** ([#12](https://github.com/cyanheads/college-scorecard-mcp-server/issues/12)) — an HTTP run with `MCP_SESSION_MODE` unset now serves stateless; it previously resolved `auto` → `stateful` everywhere except the Docker image, which already pinned `stateless`. An explicit `MCP_SESSION_MODE` value still overrides it; stdio is unaffected.
- **`no_results` removed** from the declared errors of `scorecard_search_schools` and `scorecard_search_programs` — neither tool ever threw it; an empty result still returns successfully with a notice.
- **Server instructions** restated as one paragraph carrying the same guidance, matching the framework 0.13.3 scaffold shape.
- **Plugin manifests** — the Claude plugin now forwards the API key via a required, sensitive `userConfig` option instead of an empty `env` value; the Codex plugin forwards it through `env_vars`. Either previously replaced a key the user had exported with an empty string.
- **README** restructured into an overview plus a per-capability reference with corrected counts; `.env.example` documents `SCORECARD_API_KEY` and matches the framework's current defaults (e.g. `MCP_HTTP_HOST` defaults to `127.0.0.1`).

## Fixed

- **`scorecard_get_programs` CIP filter** ([#14](https://github.com/cyanheads/college-scorecard-mcp-server/issues/14)) — a dotted `cip_code` (`"11.07"`, the description's own example and what `scorecard_lookup_cip` returns) now matches the API's undotted codes instead of always returning `no_programs`. A code the school doesn't offer now fails `no_programs` rather than `school_not_found` (the per-school fetch no longer sends the filter upstream, where a non-matching code dropped the school record).
- **Credential levels** ([#15](https://github.com/cyanheads/college-scorecard-mcp-server/issues/15)) — program labels and the `credential_level` filter now match the API's own `credential.title` (5 Master's, 6 Doctoral, 7 First professional, 8 Graduate/professional certificate, 99 Non-credential). Filtering for master's is now `5` — it was documented as `7`, which selected first-professional programs.
- **`api_error` on upstream failures** — every API-backed tool's upstream failure now carries `data.reason: "api_error"` and its declared recovery hint ("Check SCORECARD_API_KEY validity and retry after a brief delay."); error code and messages unchanged.
